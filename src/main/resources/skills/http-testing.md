# HTTP testing

Results from the `http_send_*` tools, `http_fuzz` and `http_race` are recorded in the Burp **site map** (notes starting `[MCP]`), not Proxy history —
`proxy_history_search` will never find them. Use `sitemap(action=query, note_contains="[MCP]")` (or `search_in=request|response|all`
with `search_pattern`) instead. `http_send_pipeline` and `http_race(sync=last_byte)` are the exception: they write to sockets of their own, so nothing they send passes through Burp (no site map entry, no traffic rule, token rule or login macro).

## Sending
- `http_send_request`: one request, from `url` + `method` + `headers` + `body` or from `raw_request`. Start here. `http_mode` picks `AUTO`, `HTTP_1`, `HTTP_2` or `HTTP_2_IGNORE_ALPN`; `connection_id` reuses one Burp connection (the request still completes before the call returns). Burp's request options: `follow_redirects` (`never`, `always`, `same_host` or `in_scope`; Burp does not follow redirects by default), `sni` (a TLS server name other than the host), `response_timeout_ms` (Burp's own read timeout), `verify_tls`.
- Native HTTP/2: `http_send_request(url=..., http2_headers=[...])` sends the header list exactly as given, pseudo-headers included, so they can be repeated, reordered, left out or malformed (CR/LF and uppercase names reach the wire). Items are `{"name": ":path", "value": "/x"}` or `[":path", "/x"]`; a list without any pseudo-header gets the four derived from `url` and `method`, first. No Content-Length is added: put a `content-length` field in the list to send one. It goes out as HTTP/2 (`http_mode` `HTTP_2`, the default here, or `HTTP_2_IGNORE_ALPN`) and does not combine with `raw_request` or `headers`.
- `http_send_request_chain`: dependent requests (login, then use the token). A step's `extract` is an array of `{name, pattern | json_path | xpath, from}` (`from` = `body` or `header`; the pattern's first group is the value, and a header pattern runs over the `Name: value` lines, every `Set-Cookie` included) that fills `{{name}}` in later steps; extract rules are checked before the step is sent.
- `http_send_requests_parallel`: independent requests at once, across hosts.
- `http_send_raw_bytes`: exact bytes, one request and one response, when the request must not be normalised (smuggling, CRLF injection). `raw_request_hex` is byte-exact; in `raw_request`, literal `\r\n` escapes are decoded only when the text has no real line break, and a character above U+00FF sends the whole text as UTF-8.
- `http_send_pipeline`: several raw HTTP/1.1 requests over ONE socket, every response read back in order, for 0.CL and CL.TE probes where one request can draw two responses. Content-Length is never fixed. Framing is strict: a bad length or chunk stops reading with `close_reason: "error"` instead of guessing. Each response carries `framing`, `trailers` and `warnings`; `close_reason` says why reading stopped (`max_responses`, `idle`, `total_timeout`, `fin`, `rst`, `error`, or `switching_protocols` after a 101). Set `max_responses` when a probe may draw more or fewer responses than requests. `write_mode=single_write` with `write_pause_ms` writes request by request; `keep_open` plus `connection_id` continue on the same socket in a later call, only when the server kept it open.
- Pipeline bytes and timing: responses are read while the requests are still being written. Each carries `raw_response_hex` (the bytes as received, any 1xx and the chunk framing included; `raw_hex_max_bytes`, default 65536, 0 leaves it out) and `ttfb_ms`/`ttlb_ms` counted from when the request with the same index was completely written: a negative value means the response began before its request was complete, a desync signal. `decode_content=true` shows bodies with gzip or deflate undone; `sni` sets the TLS server name. A request item can pause mid-write, as in Turbo: `pause_before` (n > 0 sends the first n-1 bytes, n < 0 holds the last |n| back), `pause_markers` (after each occurrence of a string) and `pause_ms` (default 1000; a pause ends early once response bytes arrive). The bytes of an unfinished response come back as `partial_response`, bytes past the last response as `unparsed`.
- `http_state(action=pipeline_connections)` lists the sockets `keep_open` kept and closes them (`close` with their ids, `close_all`, plus `force` for one a call is using). A kept socket nobody uses for 120 s is closed by itself.

## Varying
- `http_fuzz`: Burp Intruder's attack types. Mark positions with `FUZZ` or `§value§` pairs (the pair not being fuzzed keeps its value), or give `positions` offsets. `attack_mode=sniper` (default) fuzzes one position at a time while the others keep their value (every `FUZZ` takes the payload at once), `battering_ram` puts the same payload in every position, `pitchfork` walks one payload set per position in step and `cluster_bomb` sends every combination. Payloads come from `payloads` and/or a built-in `payload_library` (`xss`, `sqli`, `traversal`, `ssti`, `cmdi`, `ssrf`, `xxe`, `crlf`, `nosqli`, `open_redirect`, `prototype_pollution`), or one set per position from `payload_sets` (each an array, a library name or `{payloads, library}`); `encoders` (`url`, `url_all`, `double_url`, `json`, `base64`, `base64url`, `html`, `hex`, `raw`) run on each payload in order. For example `http_fuzz(request=..., host=..., attack_mode=pitchfork, payload_sets=[...], encoders=["url"])`.
- A fuzz run sends one request at a time unless `concurrency` (at most 50) says otherwise; `rate_limit` caps the requests started per second and `max_requests` (default 10000) the run. `stop_on_match` stops at the first matching response, and a failed request is recorded without stopping the run. Every response is clustered by status and body similarity (`cluster_similarity`, default 90) with timing outliers: the small clusters are the anomalies. `hide_status`, `filter_length`, `grep_regex` and `hide_regex` only shorten the list (hidden responses still count in the summary); `report=clusters` lists one line per request plus one full exchange per cluster, `report=summary` the summary alone.
- `http_race`: simultaneous requests for race conditions (`count`, or `FUZZ` with `payloads`), released together behind a real synchronisation barrier. `sync=single_packet` (default) is the HTTP/2 single-packet attack through Burp's parallel sender: the final frames of every request leave in one TCP packet, so the target must speak HTTP/2 (`http_mode=HTTP_2_IGNORE_ALPN` forces it without ALPN). `sync=last_byte` (the default with `http_mode=HTTP_1`) is for HTTP/1.1: every request is written on a connection of its own except for its last byte, and the last bytes go out back to back once every connection is ready (at most 256 connections; `sni` sets the TLS server name). It reports `ttfb_ms`/`ttlb_ms` per request and the `release_spread_us`, and bypasses Burp. For example `http_race(request=..., host=..., count=20, sync=last_byte)`.
- Race results are clustered by status and body similarity with timing outliers; `race_condition_likely` is true when identical requests were answered in more than one way. Alike responses do not rule a race out: check the application state too. For HTTP/3, several endpoints at once or a scripted sequence, use `turbo_run`.
- After a substitution (`http_fuzz`, `http_race`) or when a raw request's Content-Length does not match its body (`http_send_request`, unless `auto_fix_content_length=false`), Content-Length is recomputed in the bytes actually sent. Only the header block's bare line feeds become CRLF; the body is sent as typed. `http_send_raw_bytes` and `http_send_pipeline` change nothing.
- `timeout_ms` (0 = no hard timeout, at most 600000, default 25000) bounds one request, each chain step or fuzz request, a whole parallel batch or race. A timed-out send returns `is_timeout: true`. A number out of range (`count`, `concurrency`, `max_responses`, ...) is clamped and reported in `notes` instead of being refused.
- `analyze(action=http_variations)`, `analyze(action=http_keywords)`, `analyze(action=diff)`: compare responses.

## Rules and sessions
- `http_state(action=cookie_jar_get)`, `http_state(action=cookie_jar_set)`, `http_state(action=cookie_jar_delete)`: inspect, seed or remove Burp's cookies.
- `http_rule(action=traffic_rule_set, direction=request|response, rule_action=...)` rewrites outgoing traffic: `rule_action=modify` (default) adds, removes or replaces headers, written exactly as given (CR/LF, odd spacing or a missing colon included); `drop` suppresses the request and `spoof_response` answers it with the `spoof_response` text without sending it (both `direction=request` only). `tool_filter` limits a rule to traffic from some Burp tools; Raijin's own unauthenticated probes (`auth_diff`, `autorize`, `probe(action=idor)`) only get rules whose `tool_filter` names `EXTENSIONS`. List and remove with `http_rule(action=traffic_rule_list)` and `http_rule(action=traffic_rule_remove)`.
- `http_rule(action=token_rule_create)`, `http_rule(action=token_rule_list)`, `http_rule(action=token_rule_remove)`: extract a value from responses and inject it into later requests to keep CSRF or session tokens fresh. `extract_json_path` (`$.data.token`) or `extract_xpath` (`//input[@name='csrf']/@value`) selects the value; `extract_regex` takes its first group (else the whole match), after a path from the selected value. `extract_from=header` reads every line of `extract_header_name`, each `Set-Cookie` included. The value goes into a `header`, `cookie`, `body` (form parameter), `query` (URL parameter) or `json` value (`inject_name` is then a JSONPath naming one value, replaced in place); a value with CR/LF is never written. `inject_value_template` renders `{value}`, or an encoded `{value|url}`, `{value|base64|url}`, ... (the `http_fuzz` encoders); `inject_if_missing=false` only updates requests that already carry it. Internal unauthenticated probes never receive it. For example `http_rule(action=token_rule_create, rule_name=jwt, scope=suite, extract_from=body, extract_json_path=$.data.token, inject_into=header, inject_name=Authorization, inject_value_template="Bearer {value}")`.
- Login macros re-establish an expired session on their own: `http_rule(action=macro_set, name=..., steps=[...], scope=suite)` stores login requests (`http_send_request_chain` steps, at most 20, whose `extract` feeds `{{name}}` in later steps). When a covered response shows an expired session (its status is in `trigger_status`, default `[401]`, or `trigger_regex` matches the status line, headers and body), the steps are replayed and the original request is sent once more; that response replaces the expired one, and the tool result reports `reauthenticated` with the macro's name. Cookies the steps set replace same-named cookies in covered requests (they are never added), and token rules extract from the step responses.
- Macro safeguards: Proxy traffic is left alone by default (`tool_filter`), only a request that carried credentials triggers a macro (`require_credentials`), and neither the steps, the retry nor Raijin's internal probes ever trigger one. A macro has one run at a time and runs by itself at most every `min_interval_ms` (default 5000), with `step_timeout_ms` (default 15000) per step and for the retry and 60 s per run; after `max_failures` (default 3) runs in a row that did not help it suspends itself. While a macro is enabled it also replaces a deliberately stale session cookie: set `enabled=false` to send one. `http_rule(action=macro_run, name=...)` runs it now, to prime the session or debug the steps (a run whose steps all succeed resumes a suspended macro); `http_rule(action=macro_list)` shows runs, failures and suspension; `http_rule(action=macro_remove, name=...)` deletes it.

Hand a request to the Burp UI with `send_to_tool(action=repeater)`, `send_to_tool(action=intruder)`, `send_to_tool(action=comparer)`, `send_to_tool(action=decoder)` or `organizer(action=send)`.
Inspect parameters first with `analyze(action=extract_params)` and `analyze(action=insertion_points)`.

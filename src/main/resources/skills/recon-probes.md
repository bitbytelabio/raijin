# Recon and probes

Add the target with `scope(action=include)` first. Every request these tools send is checked against Burp's scope by the operator's `mcp_scope_mode`: `warn` (default) sends it and adds `scope_warning` to the result, `enforce` refuses it (`out_of_scope: true`). Content discovery checks every path and reports `skipped_out_of_scope` / `sent_out_of_scope`. Probes resend a request many times, so do not point them at requests that change data (a delete, a payment) unless you mean to.

## Recon
- `recon(action=fingerprint)`: technology and WAF fingerprinting from one GET.
- `recon(action=content_discovery, base_url=..., paths=[...])`: up to 2000 paths per call. Not-found behaviour is learned first from made-up paths of several shapes (plain, directory, `.json`, `.php`, your extensions), so a site that answers 200 to everything, echoes the path or redirects every unknown path gives no false hits. A 429 is waited out and the pace slowed; if blocking persists the scan stops with `stopped_at` so you can continue later.
- `recon(action=param_mine, url=...)`: hidden parameters, Param Miner style: many names per request, each with its own canary, and a binary search inside a bucket only when its response stands out, so the whole bundled list costs a few hundred requests. `mode=reflection` (default) reports names whose value is echoed back; `mode=diff` reports names that change the status, body, `Location`, `Set-Cookie` or `X-Cache` without reflecting, judged against repeated baselines; `mode=both` reports both. `inject_in` = `query` (default), `body`, `json_body`, `cookie` or `header`. Omit `candidates` to use the bundled list (`param-miner-params`; `param-miner-headers` for `header`); a candidate may be `name~value` (`%s` = canary, `%h` = target host). `headers`, `cookies` and `body` shape the base request, `cache_buster` (default on) keeps responses out of caches (left off, with `cache_buster_dropped`, when the target rejects unknown query parameters), `offset`/`limit` page through the list (continue from `next_offset`), `bucket_size` and `max_requests` (default 500) bound the run.
- `recon(action=js_endpoints)`: endpoints from JavaScript already in proxy history (`.js`, `.mjs`, `.cjs`): quoted paths, full URLs and template literals (`/users/${id}` comes back as `/users/{id}`). Source maps are read when they are in history (original file names, endpoints in embedded sources); maps a script only points to (`sourceMappingURL`, `SourceMap` header) are listed, and requested with `fetch_source_maps=true`. Browse the target first.

## Probes
- `probe(action=cors)`: sends an unrelated origin, `null`, and origins built from the target's own host (prefix and suffix matches, an unescaped dot, `_` and subdomain tricks, the `http://` origin), each as a GET and as an `OPTIONS` preflight; flags a reflected origin, credentials, and a missing `Vary: Origin`.
- `probe(action=cache)`: web cache poisoning and web cache deception. It reads the cache state from the response headers first. Poisoning sends headers and cookies a cache often leaves out of its key, each under its own throwaway cache-buster, then asks for the same URL without the input and without a session: the changed response coming back confirms it. Nothing is sent if the cache ignores the query string. An input that works by changing the status, a redirect or the path is sent only once a new cache-buster value is seen to get a cache entry of its own (the others are listed under `skipped`); a changed status or redirect whose storage cannot be checked without risk to other visitors, or that a visitor without the input then gets too, is `inconclusive`, never confirmed. `stopped` says why a run ended early: `request_budget`, `rate_limited`, `baseline_changed` (the page now answers everyone differently) or `cache_buster_ignored` (a planted response reached every visitor: have the page purged). Deception requests static-looking variants of a page (`/page/x.css`, `/page;x.css`, ...) as the user, then without a session. Pass the logged-in user's `headers` to prove a private page gets stored; `checks` (`poisoning`, `deception`), `probe_headers`/`probe_cookies` (`name` or `name~value`) and `max_requests` (default 150) tune it.
- `probe(action=graphql)`: `mode=probe` (default) is the introspection/suggestion verdict; `query_templates` builds a runnable query/mutation/subscription per field; `poi_scan` flags security-interesting fields (auth, privileged, PII, payment, database, debugging, files; `custom_keywords` match literally), deprecated fields and custom scalars at their shortest path, through interfaces and unions; `cycles_scan` lists every cycle (deep-nesting/DoS risk) with `cyclic_types`; `batch_attack` expands `$[INT:first:last]`/`$[LIST]` into aliased operations in one request (2FA brute force, IDOR enumeration, rate limits; generates only unless `send`); `fingerprint_engine` names the backend; `bruteforce_schema` rebuilds the schema from error messages when introspection is off (stops at `max_requests`, never sends an executable document); `subscription_probe` checks subscriptions over WebSocket for both protocols (`graphql-transport-ws` and the legacy one) and reports `handshake_accepted`, `init_requires_auth`, `subscription_accepted`, `subscription_requires_auth` (credentials in `headers` and `connection_payload`; the anonymous session keeps only `Host`, `Origin` and `User-Agent` of your headers). Every mode takes `headers` / `auto_headers`; an unreachable target is one error.
- `probe(action=injection, request=..., host=...)`: put `FUZZ` anywhere in the raw request (request line, any header such as `Cookie: id=FUZZ`, or the body). Each payload is written in the encoding that position needs (`encoding` overrides it) and Content-Length is recomputed. Classes: `sqli`, `nosqli`, `cmdi`, `ssti`, `lfi` (or `traversal`), `xxe`, `ssrf`, `xss`, `open_redirect`, `crlf`; all ten (about 130 requests) unless `classes` narrows them. `base_value` (default `1`) is the value the baseline sends at `FUZZ`; the boolean and operator checks only narrow the query, so it must match a real row or document. `ssrf`, `xxe` and `cmdi` also confirm out of band through Collaborator (`oob`, `oob_wait_seconds`; skipped with a reason on Community). A finding needs a difference from the baseline that the payload explains: a timeout is never evidence, a delay must repeat while a zero-delay control stays fast, a TRUE/FALSE difference must hold over three rounds. Each finding carries `payload`, `confidence` (`certain`, `firm`, `tentative`) and `evidence` (what was sent, the baseline next to the probe). `time_budget_seconds` (default 300) stops new probes and lists `classes_not_completed`; late out-of-band hits come back in the next call as `late_oob_interactions`.
- `auth_diff` (one request) and `probe(action=access_control)` (many requests): compare identities. A level is `{name, header_name, header_value}`, or `headers` for several (session cookie plus CSRF header) and `remove_headers`; its headers replace the request's own, and a level named `none`, `unauth` or `anonymous` is sent without any credential header. Each level reports `headers_set`, `headers_removed` and `credential_headers_kept`; findings have an `id` and `severity` (`all_identical`, `unauth_accessible`, `unauth_reads_protected`, ...). Refusals that look alike (same 401/403/404, a login redirect, a 200 login or denial page) are informational, never high or critical; a JSON body counts as a refusal only by its top-level error, message or 401/403 code, not by words in its data. Pass `denied_regex` when the application refuses with a 200 the built-in check does not recognise. A level without a response is listed under `errors`. `autorize(action=set_rule)` is the live counterpart on proxy traffic.
- `probe(action=idor)`: horizontal IDOR with canary confirmation. Give the request identity A makes to its own object, and `identities` that each declare `object_id` (a resource it owns) and `canary` (a string only in its own data). The id is swapped at its parameter boundary only (one path segment, one query/form/cookie/header value, one JSON value), replayed under every other identity, and a cross-user read is CONFIRMED only when the owner's canary appears in the reader's response. Pin the id with `id_value`, `id_location` and `id_name` (parameter name, JSON path, or path segment index) when auto-detection picks the wrong one; a pinned `id_value` may also begin a path segment (`42` of `/users/42-alice`). `transforms` and `enumerate` (at most 25; a larger value is clamped) add encoded and neighbouring ids, reported only when the answer is neither the reader's own view nor a not-found. When the unmodified request does not give the reader its own object (`own_view: false`, a login or denial page included), only a canary can grade a transformed id above info.
- `probe(action=jwt)`: decode first with `util(action=jwt_decode)`. Modes: `analyze`, `forge_none`, `alg_confusion`, `crack`, `sign` (HMAC secret), `sign_key`, `verify` (says why a key fails), `encrypt`, `decrypt`, `embed_jwk`, `empty_hmac`, `psychic`, `header_url`. Signing modes keep the payload byte for byte unless `payload_overrides` names claims. `mode=header_url` with `key_id`, `header=jku|x5u` and `url` returns the signed token plus `host.body`, the JWK set or PEM certificate chain to serve at that URL (without `key_id` it only sets the header). `decrypt` refuses a password-based token asking for more than 1,000,000 PBES2 iterations.
- `jwt_keys`: generate, import, list, export or delete a key (RSA, EC, OKP, oct, password). Each key lists the `modes` it supports (X25519/X448 keys encrypt and decrypt, they do not sign). `list` and `export` omit private material unless `include_private` is true.
- `api_import_openapi`: import an OpenAPI 3.0/3.1 or Swagger 2.0 document (JSON or YAML text in `spec_json`; `spec_url` when its server URL is relative) as test requests, added to the site map and optionally sent (`send_requests`). A server URL naming a host that cannot be used is an error, never a fallback to the `spec_url` host. The result lists `security_schemes` and each endpoint's `security`.

Workflow: fingerprint, discover, mine parameters, then probe. Treat a probe hit as a lead; confirm it with `http_send_request`, then record it with `findings(action=add)`.

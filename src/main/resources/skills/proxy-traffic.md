# Proxy traffic

- Read: `proxy_history` (paged with `start_index`/`count`; filters `host`, `method`, `status_code`, `status_code_range`, `mime_type`, `in_scope_only`), `proxy_history_search` (regex over `url`, `request`, `response` or `both`), `websocket(action=history)` and `websocket(action=history_search)` (filters `websocket_id`, `url`, `direction`, and `host` for the history). This only covers traffic that passed through Burp's Proxy: requests sent by `http_send_*` or Turbo land in the **site map** instead (see the `http-testing` skill); use `sitemap(action=query)` for those. Paging above the cap is served at the cap with a note.
- Keep results small: metadata only is the default. `include_request` / `include_response` add the full text (and unmask `Cookie`, `Authorization` and other sensitive request headers, which are otherwise redacted); `max_response_length` cuts it.
- Annotate: `proxy_annotate` marks items worth returning to; `sitemap(action=annotate)` does the same for site map entries, `organizer(action=annotate)` for Organizer items. Burp's Montoya API has no way to annotate Repeater tabs, Intruder runs or the Logger from an extension.
- Intercept: `proxy_intercept(action=status|enable|disable)` drives Burp's own Intercept tab; turn it back off when finished or the browser hangs.
- Hold and edit live traffic: `proxy_intercept(action=hold)` parks proxied requests and/or responses (`target=request|response|both`, filters `match_host`, `match_url`, `match_method`, `in_scope_only`) just before they are sent, after Burp's Intercept tab and the proxy rules, so what you edit is what goes on the wire. `proxy_intercept(action=list_held, wait_seconds=...)` lists them with an `id` and `expires_in_ms`; `proxy_intercept(action=forward, id=...)` sends one as it is or edited (`raw` replacement, `method`, `path`, `status_code`, `set_headers`, `remove_headers`, `body`; CR/LF allowed in headers), `proxy_intercept(action=drop, id=...)` discards it, `all=true` does either for every held message, and `proxy_intercept(action=release)` stops holding and forwards everything. A message nobody decides on within `timeout_seconds` (default 60) is forwarded unchanged, at most `max_held` (default 20) are held at once, and after 3 timeouts in a row holding stops by itself, so the browser is never stuck.
- Rules: `proxy_rule(action=set_request_rule|set_response_rule, rule_action=modify|drop|tag)`, `proxy_rule(action=list)`, `proxy_rule(action=remove)`. Match on `match_host` (a glob such as `*.example.com`, or a regex), `match_url`, `match_method`, `match_header`, `match_body`, `match_status`. `modify` can add, remove, replace or set headers (`modify_set_header` replaces every occurrence or adds the header; header lines are sent as written, CR/LF included), rewrite the body (`modify_body_regex`), the method and path of a request (`modify_method`, `modify_path`, `modify_path_regex` with `$1` groups) or the status of a response (`modify_status`). Config-level equivalents: `config(action=match_replace_add)`, `config(action=match_replace_list)`, `config(action=match_replace_remove)`.
- Auth: `proxy_auto_auth` sets an auth header (replacing an existing one) on every proxied request to a host pattern. For live broken-access-control detection, `autorize(action=set_rule)` replays matching proxied requests under other identities in the background and diffs the responses; browse the app as normal afterwards. Only authenticated originals are replayed (no credentials, 401 or 404 are skipped), `POST`/`PUT`/`DELETE`/`PATCH` only with `include_mutating=true`, and each endpoint once per query string. Matches persist per Burp project with each identity's replay: read them with `autorize(action=list_matches)` (`include_replays`, or `match_id` for one in full); critical/high ones also go to `findings`. Use `auth_diff` or `probe(action=access_control)` instead for a one-off check of requests you already have.
- Mining: `recon(action=js_endpoints)` and `analyze(action=passive_intel)` summarise what traffic already revealed.

## WebSockets

- `websocket(action=create)` opens a connection (`url`, `headers`, `subprotocol`); `websocket(action=list)` shows tracked connections, including those Burp's Proxy saw. Connections opened by Burp tools can be read but not written to.
- Send with `websocket(action=send_text)` or `websocket(action=send_binary)` (base64, standard or URL-safe, padding optional). Each send returns the `message_index` of the sent frame.
- Wait instead of polling: `websocket(action=wait_message, connection_id=..., since_index=<message_index>)` blocks until a frame recorded after that index matches `direction` (default `server_to_client`), `message_type` (`TEXT`/`BINARY`) and `pattern`, the connection closes, or `timeout_ms` passes (default 10000, at most 300000). A reply that arrived before the call is found at once. It returns `matched`, the message or a `reason` (`timeout`, `connection_closed`), and `next_since_index` to pass as `since_index` for the next wait. Without `since_index` only frames arriving after the call count.
- Read the buffer with `websocket(action=get_messages)` from `since_index`: no frame is skipped, and the result reports `oldest_index`, `next_index`, `has_more` and `missed_messages` (frames evicted before you read them). A binary frame's payload is base64 and its `length` the size in bytes.
- Fuzz: `websocket(action=fuzz)` sends each payload (`payloads` and/or `payload_library`, optionally placed in a `template` at its `marker`, `payload_encoding=json` to escape it for a JSON string) as one message over an open `connection_id`, or over a fresh connection per payload with `url` for servers that close on bad input; `setup_messages` go first on each connection. Per payload it returns the frames it triggered, `response_ms` and a cluster; small `clusters` are the anomalies. `delay_ms`, `window_ms`, `idle_ms` and `timeout_ms` shape the timing; a stopped run gives `next_index` to pass back as `start_index`.
- Intercept rules: `websocket(action=set_intercept_rule, rule_action=modify|drop|tag)` with `match_url`, `match_message`, `direction` and `message_type`; `websocket(action=list_intercept_rules)` lists them in evaluation order, `websocket(action=remove_intercept_rule)` removes one. Binary frames are matched and rewritten as ISO-8859-1 text, so `\xNN` matches one byte; a rule without `message_type` applies to both kinds.
- Regexes in `wait_message`, `fuzz` and the history search ignore case; start the pattern with `(?-i)` for an exact match.
